# CCG RFP – Scenario 5: Secure Renewal Payment (demo build)

Serve7 demo for the CAA Club Group (CCG) contact centre RFP, Scenario 5. **Synthetic data only.** The RFP agenda is
confidential: do not copy its text into this repo.
Analysis and plan: Claude Doc "CCG RFP – Scenario 5: Secure Renewal Payment (analysis & build plan)".

**Payment partner (default `PaymentPartnerMode=simulated_vendor`):** the secure segment is presented as a hand-over to a
third-party PCI partner (PCI Pal / Sequence Shift style): a hand-over message, a different voice, and partner-shaped
results (session id, transaction id, auth code, masked PAN) stored as contact attributes `s5_partner_*`. **Simulated:** no vendor is
called and no sandbox is needed. Say so when labelling capabilities. Set the spoken name with `PaymentPartnerName`.
Spoken card numbers outside the keypad segment are masked by Contact Lens PII redaction (enabled in the flow).

Design rule: **card data never enters the ACXD application.** ACXD runs the conversation. The Connect flow
`ccg-s5-secure-payment` pauses recording, takes the card by keypad (encrypted), and charges it once.

## Deploy into any account (existing Connect instance)

From AWS CloudShell in the target account (ca-central-1):

```bash
cd ~ && rm -rf ccg-s5 && unzip -oq ccg-s5-scenario5.zip
INSTANCE_ID=<connect-instance-id> bash ccg-s5/scripts/cloudshell-setup.sh   # no INSTANCE_ID = list instances and stop
```

It runs a permission pre-check (`scripts/preflight.sh`), creates the encryption key + secrets, its own code bucket
`ccg-s5-artifacts-<account>-<region>`, the `ccg-s5` stack and synthetic data, then a smoke test (`scripts/smoke.sh`)
and writes the six ACXD data requests for this account to `~/ccg-s5-acxd/` (`scripts/acxd-datarequests.py`; paste the
API key from Secrets Manager in the ACXD UI). It only adds `ccg-s5*` resources plus one encryption key and one Lambda
association on the instance; existing flows, queues, users and numbers are not changed.

Remove everything: `bash ccg-s5/scripts/teardown.sh` (asks for the account id; secrets keep a 7-day recovery window).

## Must verify on first deploy
- Store customer input ciphertext decrypts with the `AmazonConnect` / RSA-OAEP-SHA512 provider used in `payment/handler.py`.
  It is tested offline with the same SDK; confirm against a real call.
- Recording of the automated (IVR/ACXD) part: confirm the automated-interaction recording setting pauses too. The
  flow sets `RecordedParticipants: []`; the console block has a separate automated-interaction toggle.
- `UpdateContactTextToSpeechVoice` (partner voice switch) is accepted as written; otherwise use the Set voice block.
- Contact Lens post-call analytics still run after the analytics settings are re-enabled at `recording-on`.

## Operate from GitHub (no CloudShell)

Workflow `.github/workflows/ccg-s5.yml` (source: `ci/ccg-s5.workflow.yml`) assumes the role `serve7-ccg-s5-ci`
in 480315222980 through OIDC (main branch only). One-time setup: `bash demos/ccg-s5/ci/setup-github-trust.sh` in CloudShell.

Open an issue titled `ccg-s5: <command> [argument]` (only `milosjovanic-serve7`); the result is posted as a comment and the issue closes.

| Command | What it does |
|---|---|
| `status [hours]` | recent calls, payments, policy status |
| `reset` | reseed synthetic data, clear payments and notes (before every demo run) |
| `deploy` | build + deploy the stack (SMS on, returns to the main flow), then update `ccg-s5-main` |
| `main-flow` | update only the main voice flow |
| `transcript [contact-id]` | Contact Lens transcript + recording files for a call (default: latest) |
| `diag [minutes]` | Connect flow steps + Lambda logs |
| `gateway-down` / `gateway-normal` | simulate the payment system outage objection |
| `test` | unit tests + template lint |

PRs touching `demos/ccg-s5/**` run the tests automatically. ACXD changes (prompt, data requests) are still imported in the ACXD UI and deployed with Build & deploy.
